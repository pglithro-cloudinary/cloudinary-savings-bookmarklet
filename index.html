Image savings bookmarklet

A one-click browser bookmark for any site. It works out which domains are actually serving that page's imagery, measures them against Cloudinary with f_auto / q_auto:eco, and overlays the byte savings in green. Toggle domains in or out on the fly, and when something is blocked it tells you exactly what and why.

How to install it

Chrome / Edge / Firefox (easiest)

  1. Show your bookmarks bar if it's hidden: ⌘⇧B on Mac, Ctrl+Shift+B on Windows.
  2. Drag the green ⬇ Cloudinary Savings button above onto the bookmarks bar.
  3. That's it — the bookmark is now a mini script rather than a link.

Safari

Safari won't let you drag a bookmarklet straight to the Favourites bar, so add it manually:

  1. Show the Favourites bar: View → Show Favourites Bar.
  2. Bookmark any page (⌘D) into Favourites and name it Cloudinary Savings.
  3. Open Bookmarks → Edit Bookmarks, right-click your new bookmark and choose Edit Address.
  4. Copy the code from the box below and paste it in as the address, then press Enter.

Manual install (any browser)

  1. Copy the code below.
  2. Create a new bookmark and paste the code into the URL / Address field (not the name field).
  3. Save. Don't paste it into the address bar — most browsers strip the javascript: prefix when you type there.

How to use it

  1. Go to any image-heavy page — a category or product listing works best.
  2. Scroll down so the lazy-loaded images actually load. The bookmarklet only sees images already in the DOM.
  3. Click the ⬇ Cloudinary Savings bookmark.
  4. Each measured image gets a bright green badge with its saving. Badges scale to the image — small nav thumbnails get a compact percentage-only badge so they stay readable.
  5. Hit Diagnostics in the panel if anything looks wrong: it reports CSP violations, helper reachability and per-domain failure reasons.
  6. A green panel appears listing every image domain on the page, with the significant ones already ticked. It measures those, then shows the total.
  7. Tick or untick any domain to add or remove it — newly ticked domains are measured on demand.
  8. Open the console (⌘⌥J / F12) for the full per-image breakdown with both URLs and both content types.
  9. Use Hide overlays in the summary panel to flip between the clean page and the annotated one while presenting.

How it picks domains

A page's images usually come from several hosts — the product CDN, a logo, an analytics pixel, a consent-banner icon. Only some of them are worth talking about. The bookmarklet groups every image by host and counts how many render larger than 100×100, which is the line between real content imagery and icons, swatches and tracking pixels.

Any domain with two or more such images is ticked by default and measured. A domain with just one is listed but left unticked. Ticking a domain measures it on demand; unticking removes it from the total and hides its badges.

Domains with nothing over 100×100 — consent-banner icons, tracking pixels, colour swatches — are moved out of the main list into Advanced, so the list stays about the imagery that matters. They're still there and still tickable if you want one, and anything you do tick moves back into the main list so it's obvious what's feeding the total.

Scene7 / Dynamic Media hosts get a SCENE7 tag in the list. That's cosmetic labelling only — it's confirmed by asking the host's Image Serving API for its #S7Z signature — and it no longer gates anything. Scene7 sites behave exactly like every other site.

When something is blocked

Plenty of pages will refuse part of this, so the Diagnostics button reports what happened rather than leaving you with a silent zero:

  • CSP violations — captured live from the browser's securitypolicyviolation event, with the directive and the blocked URL. This is the single most useful signal when a run comes back empty.
  • Helper reachability — whether the measuring iframe loaded at all. If frame-src is restricted, it says so instead of timing out mysteriously.
  • Per-domain failures, grouped by cause: no access-control-allow-origin (the host refuses cross-origin reads — nothing client-side can fix it), no content-length (chunked response, size unreadable), HTTP 403 (hotlink protection), or a Cloudinary 401/403, which means the cloud isn't allowed to fetch that domain.

Measurement itself degrades gracefully: a HEAD is tried first, and if the host rejects it or omits content-length, it retries with a GET and cancels the body as soon as the headers arrive. When a fetch fails outright, a no-cors probe distinguishes "this host won't let us read it" from "we couldn't reach it at all".

Why it needs a helper page

George (Asda), the site this was first built for, is served behind Cloudflare with a strict Content-Security-Policy — a good example of what you'll hit elsewhere. Its connect-src allowlist covers Asda's own domains and their analytics vendors — and nothing else. That means a fetch() fired from the page is refused for both res.cloudinary.com and asda.scene7.com, which is why the earlier version of this tool reported 0.00 KB and NaN% for everything.

The CSP also sets img-src without Cloudinary on it, so the page can't even display a Cloudinary-served image. A true side-by-side visual swap isn't possible from a bookmarklet.

What the CSP does allow is frame-src * — the page may embed any origin. A cross-origin iframe is a separate document governed by its own CSP, not the parent's. So the bookmarklet drops a hidden iframe pointing at helper.html on this domain, the helper does the measuring (both Scene7 and Cloudinary send access-control-allow-origin: *, so it's allowed to read content-length), and posts the numbers back via postMessage. The page itself only ever draws DOM overlays, which CSP doesn't restrict.

The helper can only read a resource's size when that server explicitly opts in with an access-control-allow-origin header — the browser enforces that, not the helper — so framing it grants no read access the framing page didn't already have.

Good to know

  • The numbers are like-for-like. Scene7 already negotiates AVIF when the browser asks for it, so both sides are requested with the same Accept header. Measuring Scene7 as JPEG against Cloudinary as AVIF would overstate the win by roughly 7 points — worth knowing if their engineers check.
  • Savings reflect format and quality only (f_auto, q_auto:eco) — no resizing. Adding responsive sizing pushes the numbers considerably further, which is a good thing to say out loud in the room.
  • Sizes come from content-length on a HEAD request; anything served without that header is skipped from the totals.
  • Totals count each unique image URL once, even when the same image appears several times on the page.
  • Badges are drawn in a fixed overlay layer rather than by wrapping each image, so the page's own layout is never touched. They reposition on scroll and resize.
  • Only <img> elements are inspected — CSS background images and <canvas> aren't.
  • The bookmarklet depends on helper.html on this GitHub Pages site being reachable. If the helper can't be reached you'll get an explicit alert rather than silent zeroes.
  • Cloudinary fetch mode must be allowed to pull from the customer's domain. If every Cloudinary side comes back as an error, check the cloud's fetch restrictions before assuming the tool is broken.
  • Refresh the page to clear all the overlays.
