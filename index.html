Scene7 → Cloudinary savings bookmarklet

A one-click browser bookmark for any site running Adobe Scene7 / Dynamic Media. It detects Scene7 imagery from the URL structure, proves the host really is a Scene7 image server before claiming anything, then measures every image against Cloudinary with f_auto / q_auto:eco and overlays the byte savings in green. Works around the Content-Security-Policy retail sites increasingly enforce.

Drag this button to your bookmarks bar 👇

⬇ Cloudinary Savings

Clicking it here won't do anything useful — it needs to run on a George page.

How to install it

Chrome / Edge / Firefox (easiest)

  1. Show your bookmarks bar if it's hidden: ⌘⇧B on Mac, Ctrl+Shift+B on Windows.
  2. Drag the green ⬇ Cloudinary Savings button above onto the bookmarks bar.
  3. That's it — the bookmark is now a mini script rather than a link.

Safari

Safari won't let you drag a bookmarklet straight to the Favourites bar, so add it manually:

  1. Show the Favourites bar: View → Show Favourites Bar.
  2. Bookmark any page (⌘D) into Favourites and name it Cloudinary Savings.
  3. Open Bookmarks → Edit Bookmarks, right-click your new bookmark and choose Edit Address.
  4. Copy the code from the box below and paste it in as the address, then press Enter.

Manual install (any browser)

  1. Copy the code below.
  2. Create a new bookmark and paste the code into the URL / Address field (not the name field).
  3. Save. Don't paste it into the address bar — most browsers strip the javascript: prefix when you type there.

How to use it

  1. Go to any page with product imagery on a Scene7 site — a category listing works best.
  2. Scroll down so the lazy-loaded images actually load. The bookmarklet only sees images already in the DOM.
  3. Click the ⬇ Cloudinary Savings bookmark.
  4. Each Scene7 image gets a bright green badge with its saving, and a summary panel appears bottom-right with the page total. Badges scale to the image — small nav thumbnails get a compact percentage-only badge so they stay readable.
  5. A green panel appears: first Checking hosts… while it proves Scene7, then Measuring…, then the result. Give it a few seconds.
  6. Open the console (⌘⌥J / F12) for the full per-image breakdown with both URLs and both content types.
  7. Use Hide overlays in the summary panel to flip between the clean page and the annotated one while presenting.

How it knows it's Scene7

Most Scene7 customers don't serve from *.scene7.com — they use a vanity CNAME like images.retailer.com, so the hostname tells you nothing. The bookmarklet scores each image URL on structure instead:

  • a *.scene7.com hostname
  • an /is/image/ or /is/content/ Image Serving path
  • Scene7 query parameters — wid, hei, qlt, fmt, resmode, op_usm, scl, defaultImage and friends
  • $preset$ macro syntax in the query string

Structure alone is a guess, so anything that scores highly gets proven against the live server before a single number is shown. Scene7's Image Serving API answers any req= command with a #S7Z OK header block in text/plain — a signature no static CDN produces, returned even for an asset that doesn't exist: 

GET https://<host>/is/image/<co>/<asset>?req=exists

#S7Z OK
#Wed Sep 16 11:31:57 UTC 2026
catalogRecord.exists=1

If a deployment blocks req= commands, it falls back to asking whether the host actually honours Scene7 resizing — ?wid=20 against ?wid=600. A static CDN returns the same bytes both times; a Scene7 server doesn't (1 KB vs 271 KB on the Asda deployment).

Only hosts that pass get measured. If nothing passes you get an explicit "couldn't verify" alert naming each host and why, rather than a confident number about a CDN that isn't Scene7. The per-host verdicts are logged to the console either way.

Why it needs a helper page

George (Asda), the site this was first built for, is served behind Cloudflare with a strict Content-Security-Policy — and it's a good example of what you'll hit elsewhere. Its connect-src allowlist covers Asda's own domains and their analytics vendors — and nothing else. That means a fetch() fired from the page is refused for both res.cloudinary.com and asda.scene7.com, which is why the earlier version of this tool reported 0.00 KB and NaN% for everything.

The CSP also sets img-src without Cloudinary on it, so the page can't even display a Cloudinary-served image. A true side-by-side visual swap isn't possible from a bookmarklet.

What the CSP does allow is frame-src * — the page may embed any origin. A cross-origin iframe is a separate document governed by its own CSP, not the parent's. So the bookmarklet drops a hidden iframe pointing at helper.html on this domain, the helper does the measuring (both Scene7 and Cloudinary send access-control-allow-origin: *, so it's allowed to read content-length), and posts the numbers back via postMessage. The page itself only ever draws DOM overlays, which CSP doesn't restrict.

The helper only measures hosts it has itself verified as Scene7 in that same session, and only through the configured Cloudinary cloud, so framing it doesn't turn it into a general-purpose measurement proxy.

Good to know

  • The numbers are like-for-like. Scene7 already negotiates AVIF when the browser asks for it, so both sides are requested with the same Accept header. Measuring Scene7 as JPEG against Cloudinary as AVIF would overstate the win by roughly 7 points — worth knowing if their engineers check.
  • Savings reflect format and quality only (f_auto, q_auto:eco) — no resizing. Adding responsive sizing pushes the numbers considerably further, which is a good thing to say out loud in the room.
  • Sizes come from content-length on a HEAD request; anything served without that header is skipped from the totals.
  • Totals count each unique image URL once, even when the same image appears several times on the page.
  • The bookmarklet depends on helper.html on this GitHub Pages site being reachable. If the helper can't be reached you'll get an explicit alert rather than silent zeroes.
  • Cloudinary fetch mode must be allowed to pull from the customer's domain. If every Cloudinary side comes back as an error, check the cloud's fetch restrictions before assuming the tool is broken.
  • Refresh the page to clear all the overlays.
